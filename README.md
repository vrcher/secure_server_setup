# 🔒 Secure Server Setup

Интерактивный bash-скрипт для быстрой и безопасной первичной настройки сервера на **Ubuntu** и **Debian**. Проходит по шагам: обновление системы, установка базовых пакетов, создание пользователя, хардненинг SSH, firewall, сетевая оптимизация и защита от базовых атак.

Каждый шаг — отдельный вопрос `y/n`, поэтому можно выполнить только то, что нужно именно вам.

---

## Поддерживаемые системы

| Дистрибутив | Версии |
|---|---|
| Ubuntu | 20.04, 22.04, 24.04, 26.04 |
| Debian | 10, 11, 12, 13 |

Скрипт сам определяет ОС через `/etc/os-release`. На неизвестных, но apt-based версиях, работа продолжится с предупреждением.

---

## Что делает скрипт

1. **Обновление системы** — `apt update && apt upgrade`
2. **Базовые пакеты** — `nano htop net-tools unzip ufw fail2ban unattended-upgrades curl`, отдельно спрашивается про **nginx**
3. **Таймзона** — установка через `timedatectl`
4. **Новый пользователь** — создаётся с sudo-правами и случайным паролем
5. **Пароль root** — генерируется случайный пароль
6. **SSH-хардненинг** (единый блок, один перезапуск в конце):
   - запрет входа root по SSH
   - смена порта SSH
   - лимиты попыток входа (`MaxAuthTries`, `LoginGraceTime`)
   - корректировка баннера (`DebianBanner no`)
7. **UFW firewall** — открывает актуальный SSH-порт, 80/443 (если ставился nginx), плюс порты по запросу
8. **fail2ban** — включение и запуск сервиса
9. **TCP-оптимизация** — BBR, буферы, backlog и связанные параметры сети
   - **9а. IP forwarding** — вынесен отдельно с предупреждением: нужен только роутеру/VPN-шлюзу, не обычному веб-серверу
10. **Защита от SYN flood** — `tcp_syncookies`
11. **DNS** — задать nameserver'ы вручную
12. **Авто security-обновления** — `unattended-upgrades`
13-14. **nginx-заглушка и скрытие версии** — выполняются, только если nginx был установлен на шаге 2
15. **Блокировка ICMP ping**
16. **Итоговые данные и перезагрузка**

## Использование

```bash
chmod +x secure_server_setup.sh
sudo ./secure_server_setup.sh
```

Скрипт должен запускаться **от root**. Работает и при запуске через `curl | bash` — ввод читается напрямую из `/dev/tty`.

```bash
curl -fsSL https://example.com/secure_server_setup.sh | sudo bash
```

> Замените URL на реальное расположение вашего скрипта.

---

## ⚠️ Важно перед запуском

- **Работайте через отдельную сессию SSH**, не закрывая текущую, пока не убедитесь, что новый пользователь/порт/правила firewall работают. Если что-то настроено неверно, у вас останется текущая сессия для отката.
- Если отключаете **root-логин по SSH**, убедитесь, что создан обычный пользователь с sudo (шаг 4) — иначе можно потерять доступ к серверу.
- При смене **SSH-порта** скрипт сам предложит открыть новый порт в UFW и спросит, оставлять ли старый (22) — но окончательная ответственность за доступность порта на вас.
- Пункт **9а (IP forwarding)** нужен **только** серверам, работающим как роутер/NAT/VPN-шлюз. Для обычного веб- или бэкенд-сервера отвечайте "нет".

## Где хранятся результаты

| Файл | Назначение |
|---|---|
| `/root/server_setup_credentials.txt` | Пароли root / нового пользователя, SSH-порт (права `600`) |
| `/var/log/secure_server_setup.log` | Полный лог выполнения скрипта |
| `*.bak.<timestamp>` | Бэкапы изменённых конфигов (`sshd_config`, `sysctl.conf`, `nginx.conf`, `resolv.conf`) рядом с оригиналами |

**После настройки:**

```bash
cat /root/server_setup_credentials.txt   # скопируйте в менеджер паролей
shred -u /root/server_setup_credentials.txt
```

---

## Откат изменений

Каждый изменённый конфиг сохраняется рядом со собой с суффиксом `.bak.<unix-timestamp>` перед правкой. Чтобы откатить, например, SSH-конфиг:

```bash
cp /etc/ssh/sshd_config.bak.<timestamp> /etc/ssh/sshd_config
systemctl restart ssh
```

## Структура вопросов (логическая зависимость)

```
Пакеты (nginx?)
   │
   ├── nginx = да ──► заглушка / скрытие версии доступны
   └── nginx = нет ─► шаги 13-14 автоматически пропускаются

SSH-порт изменён?
   │
   └──► Firewall предложит открыть именно этот порт
        и спросит, оставлять ли 22/tcp

TCP-оптимизация ≠ IP forwarding
   │
   └──► Разнесены на разные вопросы (9 и 9а),
        т.к. это разные по смыслу и риску настройки
```
